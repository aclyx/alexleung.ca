22:T6e2,<p>I’m spending far more tokens on coding agents than I used to, and I’m fine with that. I’m using the sessions to encode my preferences and taste so Codex can get the next task right. I call this “farming the session”: asking Codex to reflect on what went wrong and save the fixes in <code>AGENTS.md</code> or the relevant skill.</p>
<p>I want the review to recover the preference behind each correction. “Too wordy” might mean repeated points should go while detailed reasoning stays. If that becomes “write shorter answers,” Codex can obey the new rule and still miss what I wanted. Reading the feedback alongside the original request and draft gives it the context to propose a more precise instruction.</p>
<p>I also have automated jobs review sessions for workflow improvements, so the process doesn’t depend entirely on remembering to ask during each conversation. Looking across sessions can reveal the same preference in several corrections, which can then be consolidated into the existing guidance. Blog-specific feedback belongs in the writing skill, and a correction to an existing rule should revise it rather than sit beside it. A proposed change should point to the feedback behind it, so I can check that the new instruction reflects my taste.</p>
<p>Once the guidance is saved, the next test is whether Codex can use it without the original conversation. A successful retry in the same session still has my corrections in context; an <a href="https://www.anthropic.com/research/demystifying-evals-for-ai-agents">eval</a> can compare old and revised instructions over several fresh runs on new tasks. I’d like to one-shot every task I give an agent.
