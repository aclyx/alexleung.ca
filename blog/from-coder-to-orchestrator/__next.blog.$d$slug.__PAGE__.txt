18:T7be,<p>Implementation can run in parallel, but review and coordination still funnel back through me. That is the limit I have not solved in my AI-assisted coding workflow.</p>
<p>In early 2024, I used AI mostly for autocomplete-level work: snippets, error explanations, and small refactors. By 2026, I was using agents for larger tasks. I still write code when needed, but more of my attention now goes to constraints, review, and the edge cases the tools miss.</p>
<h2>Reviewing plans before implementation</h2>
<p>I started experimenting with Cline for straightforward tasks such as boilerplate, test scaffolding, and repetitive refactors. I avoided giving it larger tasks because it was easy to get code that looked fine but was wrong in non-obvious ways, and anything non-trivial took too much prompt back-and-forth.</p>
<p>In 2025, I switched to Claude Code and stopped asking for immediate implementation. Instead, I asked for a plan first and reviewed it.</p>
<p>Plans were often overbuilt for the actual problem, and the agent would report "done" before handling edge cases. Plan review gave me a place to question the proposed scope before implementation; it did not remove the need to inspect the result.</p>
<h2>Making the work reviewable</h2>
<p>A lot of bad output came from missing repository context, so I keep architecture preferences, testing requirements, and coding conventions in the repository guidance. That gives the agent a baseline to work from, while the task brief supplies the specific constraints and non-goals.</p>
<p>I often split planning and implementation into separate passes, turning the brief into checkpoints and running build, lint, and tests at each one.</p>
<h2>Costs and limits</h2>
<p>Frequent tool calls and retries add up, and agents struggle when a system relies on undocumented history.</p>
