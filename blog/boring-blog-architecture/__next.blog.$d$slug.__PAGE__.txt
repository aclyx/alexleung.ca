17:Tdd3,<p>I added the blog directly to the site's existing Next.js application so technical notes could live beside the rest of the site without another system to maintain. Posts are Markdown files, each route builds to static HTML, and publishing does not depend on a CMS or runtime admin surface.</p>
<h2>Markdown in, static HTML out</h2>
<p>Three constraints shaped the implementation:</p>
<ol>
<li><strong>Repo-backed Markdown</strong>: posts should live beside the rest of the site.</li>
<li><strong>Static output</strong>: each post should build into HTML during deploy.</li>
<li><strong>No admin runtime</strong>: publishing should not require a CMS, database, or editor surface.</li>
</ol>
<h2>File-backed routes at build time</h2>
<p>I created a simple utility, <code>blogApi.ts</code>, that reads directly from the file system and uses <code>gray-matter</code> to parse frontmatter. A separate <code>markdownToHtml.ts</code> pipeline converts post bodies with <code>remark</code> and <code>rehype</code>, including <code>rehype-pretty-code</code>.</p>
<p>Next.js makes it straightforward to turn a folder of markdown files into routes. I used <code>generateStaticParams</code> to tell Next.js which paths to build at compile time:</p>

<p>This ensures that <code>alexleung.ca/blog/boring-blog-architecture/</code> is just a static HTML file at deploy time, not a dynamic request.</p>
<h2>Small details keep publishing simple</h2>
<p>The details that mattered were small, but they made the blog easier to live with:</p>
<ul>
<li><strong>Typography</strong>: I used <code>@tailwindcss/typography</code> but customized it to remove the default backticks from inline code for a cleaner look.</li>
<li><strong>Metadata</strong>: Each post automatically generates its own SEO tags and JSON-LD structured data.</li>
<li><strong>Syntax Highlighting</strong>: I chose <code>rehype-pretty-code</code> (powered by Shiki). It uses the same TextMate grammars as VS Code, so the highlighting is close to what I am used to in the editor. It also generates inline styles, so there is no separate CSS import to manage.</li>
<li><strong>Sitemap</strong>: A force-static Next.js metadata route uses the same post loader at build time, so <code>sitemap.xml</code> includes each post and its publication or update date.</li>
</ul>
